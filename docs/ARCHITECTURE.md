# Arquitetura
FastAPI com adaptadores independentes para PubMed e Firecrawl. Na inicialização, a aplicação cria o esquema e habilita a extensão vector. As fontes preservam URL, data UTC de recuperação e, quando fornecidos pelo PubMed, PMID e DOI. A coluna vetorial é opcional e fica disponível para indexação futura.

O cache usa uma chave SHA-256 por adaptador e parâmetros. Respostas vazias válidas também expiram após 24 horas. A validade é verificada na leitura. Linhas expiradas podem permanecer em disco até a substituição. Cada chamada externa passa por uma reserva atômica no PostgreSQL, com intervalo mínimo de 350 ms por provedor entre reservas. Disputas retornam RateLimited ao chamador. No Firecrawl, cada reserva consome uma unidade do teto mensal UTC antes do HTTP. Falhas e timeouts mantêm a reserva, pois o provedor pode ter processado a chamada. O limite é compartilhado pelas instâncias que usam o mesmo banco. O saldo real da conta também depende de usos fora desta aplicação.

A interface Next.js utiliza uma ação de servidor para chamar POST /api/pubmed/search com um corpo JSON contendo query (1 a 300 caracteres após remover espaços nas extremidades) e limit opcional (1 a 20, padrão 5). A resposta contém articles e cached. A consulta fica fora da URL do navegador. Os serviços web e api são publicados em loopback. A indexação RAG e o provedor de IA são etapas futuras. Codex é ferramenta de desenvolvimento, não backend de inferência. Plus não inclui créditos da API OpenAI. Firecrawl MCP deve ser configurado separadamente no ambiente local; consulte https://github.com/firecrawl/firecrawl-mcp-server e mantenha a chave fora do Git.
